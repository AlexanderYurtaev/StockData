# Позиции по фьючерсам на акции — MOEX

Веб-сервис показывает **открытые и закрытые позиции физических и юридических лиц**
по фьючерсам на акции и ведущим фондовым индексам (IMOEX, MIX, MXI, RTS, RTSM)
на срочном рынке Московской биржи.

Данные — из официального отчёта биржи «Открытые позиции»
(тот же источник, что использует страница <https://www.moex.com/ru/derivatives/open-positions>).
Отчёт публикуется с лагом ~1 торговый день; нерабочие даты пропускаются автоматически.

## Возможности

- Таблица **открытых позиций**: лонг/шорт физлиц и юрлиц по каждому фьючерсу на акции
  и индексным фьючерсам (68 инструментов), изменение к предыдущему дню, сортировка,
  поиск, пагинация, избранное.
- **Сводка по рынку**: доли физлиц/юрлиц в совокупном объёме позиций, нетто-баланс;
  карточки кликабельны и ведут на страницу **«Динамика по рынку»** — те же два графика
  (чистые и абсолютные позиции), но по сумме всех инструментов, за 14/30/60/90 дней.
- **История инструмента**: два графика — чистые позиции (лонг − шорт, отдельно физлица
  и юрлица) и все четыре серии (лонг/шорт по категориям) — за 14/30/60/90 дней, 1, 3 и 5 лет,
  плюс агрегаты «открыто/закрыто» за период. На графике чистых позиций — линия цены
  базового актива (для индексных фьючерсов — цена индекса) по правой оси. На обоих
  графиках кликабельная легенда (скрытие/показ линий); для периодов длиннее 110 дней
  ось датируется с годом.
- Бейдж источника данных: реальные данные MOEX или демо-генератор (офлайн-фолбэк).

## Хранение истории

История позиций накапливается в локальном SQLite-архиве (`backend/data/positions.db`):

- **Ленивый бэкфилл задним числом** — при первом просмотре истории инструмента недостающие
  даты докачиваются с биржи и остаются в базе навсегда; повторные запросы отдаются из базы
  (90 торговых дней: ~3 с при докачке → ~20 мс из архива).
- **Фоновая синхронизация** — раз в `FP_SYNC_INTERVAL` секунд сервис обновляет срез позиций
  по всем инструментам, так что архив растёт сам по себе, по мере выхода отчётов биржи.
- **Устойчивость** — если биржа недоступна, свежий срез и уже накопленная история отдаются
  из базы; немаркированные «пустые» даты (праздники) не перекачиваются, а самая свежая дата
  всегда перепроверяется на случай лага публикации.
- **Хранение истории**: агрегаты по дням считаются при каждом полном срезе и докачке дат,
  фоновая синхронизация при старте прогревает последние 30 торговых дней
  (`FP_TOTAL_BACKFILL_DAYS`). Длинные периоды агрегатов сэмплируются (~90 точек: недели
  до года, месяцы дольше) и кэшируются навсегда, поэтому график «Динамика по рынку»
  открывается быстро; глубина истории ограничена только архивом биржи (проверено на 5 лет).

Архив включён по умолчанию; выключается `FP_DB_ENABLED=0`.

## Запуск с нуля на новой машине

### 1. Установите инструменты

- **uv** — менеджер Python и зависимостей (сам скачает нужный Python 3.12+, отдельно
  Python ставить не нужно):
  ```bash
  curl -LsSf https://astral.sh/uv/install.sh | sh          # macOS / Linux
  # Windows: powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
  ```
- **Node.js 18+ и npm**: https://nodejs.org или `brew install node`.

### 2. Получите код

Скопируйте или склонируйте папку проекта `moex-futures-positions/`.

### 3. Установите зависимости

```bash
make setup        # = cd backend && uv sync  +  cd frontend && npm install
```

`uv sync` создаст `.venv` и поставит пакеты строго по `uv.lock`.

### 4. Переменные окружения (опционально)

Сервис работает без настройки — все параметры имеют значения по умолчанию (таблица
ниже). Чтобы переопределить, есть два способа:

- файл **`backend/.env`** — читается автоматически при старте, например режим
  полностью без сети (демо-данные вместо биржи):
  ```dotenv
  FP_DATA_SOURCE=demo
  FP_DB_PATH=data/positions.db
  ```
- либо переменные перед запуском: `FP_DATA_SOURCE=demo make dev`.

### 5. Запустите

```bash
make dev          # оба сервера в текущем терминале; Ctrl+C останавливает оба
# или по отдельности: make backend, make frontend; фоновые — make stop
```

Проверка: сайт — http://localhost:5173, состояние провайдеров —
<http://127.0.0.1:8000/api/v1/system/health>, Swagger — <http://127.0.0.1:8000/docs>.
При первом запуске архив фоном прогревается (срез позиций + агрегаты за 30 торговых
дней, ~1–2 минуты); история инструментов и длинные периоды докачиваются при первом
открытии соответствующего графика.

## Запуск (кратко, для уже настроенной машины)

```bash
cd backend
uv sync                                               # окружение + зависимости из uv.lock
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
# быстрый старт без сети (демо-данные): FP_DATA_SOURCE=demo uv run uvicorn app.main:app
```

Фронтенд: `cd frontend && npm install && npm run dev`.
Или всё сразу: `make dev` (Ctrl+C останавливает оба сервера). Фоновые серверы: `make stop`.

## Автотесты (запускаются отдельно, офлайн)

```bash
cd backend
uv run pytest                                # весь набор: 19 тестов
make test                                    # то же через make
uv run pytest tests/test_api.py -k summary   # один тест по имени
```

Тесты работают **без доступа к сети** — на детерминированном демо-провайдере
(включая синтетические цены), на отдельной in-memory базе. Перед релизом достаточно
`uv run pytest` — сеть для них не нужна и не используется.

## Конфигурация (переменные окружения с префиксом `FP_`)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `FP_DATA_SOURCE` | `auto` | `auto` (MOEX → демо), `moex`, `demo` |
| `FP_MOEX_BASE_URL` | `https://web.moex.com/moex-web-iss-api/api/v1` | Адрес API открытых позиций |
| `FP_CORS_ORIGINS` | `http://localhost:5173,…` | Разрешённые origins |
| `FP_SNAPSHOT_CACHE_TTL` | `1800` | Кэш среза позиций, сек |
| `FP_HISTORY_CACHE_TTL` | `43200` | Кэш истории, сек |
| `FP_FETCH_CONCURRENCY` | `8` | Параллельные запросы к бирже |
| `FP_HISTORY_DAYS_MAX` | `1825` | Ограничение глубины истории (5 лет) |
| `FP_DB_ENABLED` | `1` | Локальный SQLite-архив позиций |
| `FP_DB_PATH` | `data/positions.db` | Путь к файлу архива (`:memory:` — в памяти) |
| `FP_SYNC_INTERVAL` | `900` | Период фоновой синхронизации, сек (0 — выкл.) |
| `FP_TOTAL_BACKFILL_DAYS` | `30` | Сколько последних торговых дней агрегатов прогревать при старте |

## Расширение

Замысел — сервис будет расширяться, поэтому:

- **Новый источник данных** (файлы отчётов биржи, собственная БД): реализуйте контракт
  `DataProvider` (`app/providers/base.py`) и добавьте его в цепочку `DataService`.
  Цепочка автоматически даёт фолбэк и «остывание» после сбоев; архивирующий прокси
  `ArchiveProvider` можно надеть на любой источник.
- **Новые срезы рынка** (опционы, индексные и товарные фьючерсы): параметр `market`
  провайдера уже изолирован; добавьте enum в `PositionView`/параметры эндпоинтов.
- **Новые страницы/виджеты фронтенда**: роут в `App.tsx` + хук `useApi` — данные типизированы
  моделями из `src/api/types.ts`.
- **Постоянный кэш / другое хранилище**: интерфейс `PositionsDatabase` (`app/storage/db.py`)
  переносится на PostgreSQL без изменений в провайдерах.

## Тесты

```bash
cd backend && .venv/bin/python -m pytest tests/ -q
```

16 тестов покрывают все эндпоинты (фильтры, сортировки, корректность «закрытых» позиций,
агрегаты истории и сводки) и поведение локального архива: докачку недостающих дат,
отсутствие повторных запросов по закэшированным и «пустым» датам, достройку неполного
среза, устаревание.

## Методология

«Закрытые позиции» в отчёте биржи — это уменьшение числа открытых позиций к предыдущему
торговому дню. Сервис считает закрытием неотрицательную часть изменения, а открытием —
неотрицательную часть прироста, раздельно по лонгам/шортам и категориям участников.

Не является инвестиционной рекомендацией.
