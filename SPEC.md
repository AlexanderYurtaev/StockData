# Спецификация: веб-сервис «Позиции по фьючерсам на акции и индексы — MOEX»

> Этот документ — самодостаточное ТЗ. Его можно целиком передать агенту/разработчику
> для создания сервиса с нуля. Он содержит product-требования, недокументированные
> источники данных с форматами, архитектуру и список ловушек, в которые легко попасть.

## 1. Что делаем

Веб-сервис показывает **открытые и закрытые позиции физических и юридических лиц**
по фьючерсам на акции и ведущим фондовым индексам (МосБиржи, РТС) на срочном рынке
Московской биржи, а также **цену базового актива** для сопоставления с позициями.

- Фронтенд: **Vite + React + TypeScript** (реcharts для графиков, react-router).
- Бэкенд: **FastAPI** (Python 3.12+), версионированный API `/api/v1`.
- Локальное хранилище истории: **SQLite** (без внешних зависимостей).
- Стиль: светлый, лаконичный, русскоязычный интерфейс. Не является инвест-рекомендацией (дисклеймер в футере).

## 2. Источники данных (критически важные знания)

### 2.1. Позиции по категориям участников

В **ISS** (`iss.moex.com`) разбивки позиций по физ/юрлицам **отсутствует**. Она живёт во
внутреннем API страницы биржи «Открытые позиции» (https://www.moex.com/ru/derivatives/open-positions):

```
База: https://web.moex.com/moex-web-iss-api/api/v1

GET /open-position/instruments/F?date=YYYY-MM-DD&lang=ru
  → [{"charsetinfo":...}, {"assets":[{asset_code, title, type}]}]
  Список ВСЕХ фьючерсов с названиями («Фьючерсный контракт на обыкновенные акции ПАО …»).
  Состав инструментов МЕНЯЕТСЯ СО ВРЕМЕНЕМ — для исторических дат запрашивайте
  список именно на эту дату.

GET /open-position/F/{asset_code}?date=YYYY-MM-DD&lang=ru
  → [{"charsetinfo":...}, {"openpositions":[4 строки]}]
  Строки различаются полем title:
    «Кол-во контрактов, шт.»                    — сами позиции
    «Изменение к пред. торговому дню, шт.»      — дневное изменение
    «Кол-во лиц, имеющих открытые позиции»      — число лиц
  У каждой строки поля: long_fiz, short_fiz, long_jur, short_jur, total.
```

Фильтр «фьючерсы на акции» — по title содержит «обыкновенные акции» или
«привилегированные акции». Для индексных фьючерсов — title содержит «Индекс МосБиржи»
или «Индекс РТС», НО исключить: «Биткоин», «Эфириум», «юанях», «IPO», «гос. обл»
(крипто-/валютные/облигационные индексы).

Нюансы:
- Публикация с **лагом ~1 торговый день**; на выходные/праздники ответ пустой →
  идти назад по будням до первой даты с данными.
- При частых запросах API **троттлит, отвечая валидным пустым телом** — нужны ретраи
  с паузами (например, 2 ретрая, 0.6/1.2 с) и аккуратный параллелизм.
- Параллелизм ~8 запросов безопасен; больше — троттлинг.

### 2.2. Цены базовых активов и индексов (ISS, бесплатно, без ключей)

```
Акции:  https://iss.moex.com/iss/history/engines/stock/markets/shares/boards/TQBR/securities/{SECID}.json
        (если пусто — тот же путь без boards/TQBR)
Индекс: https://iss.moex.com/iss/history/engines/stock/markets/index/boards/SNDX/securities/{IMOEX|RTS}.json
Параметры: ?from=YYYY-MM-DD&till=YYYY-MM-DD&start={смещение строк}&iss.meta=off
Пагинация: по 100 строк (start += 100), пока строк >= 100.
Блок «history»: columns + data; нужны TRADEDATE и CLOSE (бывают NULL — пропускать).
```

### 2.3. Соответствие «фьючерс → базовый актив»

Тикеры часто не совпадают. Кураторский словарь (основа — актуальный список
инструментов биржи; состав меняется, старые ключи держать для архива):

```
SBRF→SBER  SBERF→SBER  SBPR→SBERP  GAZR→GAZP  GAZPF→GAZP  NOTKM→NVTK
MTSI→MTSS  BELUGA→BELU  TRNF→TRNFP  SNGR→SNGS  SNGP→SNGSP  TATN→TATN
TATP→TATP  RTKM→RTKM  RTKMP→RTKMP  PLZL→PLZL  PLZLM→PLZL  ISKJ→ABIO
SFIN→SFI  CBOM→CBOM  FESH→FESH  MDMG→MDMG  OZON→OZON
Остальные (AFKS AFLT ALRS ASTR BANE BSPB ENPG FEES FLOT GMKN HEAD HYDR IVAT
KMAZ LEAS LKOH MAGN MOEX MVID NLMK PHOR POSI RASP RNFT ROSN RUAL SGZH SIBN
SMLT SOFL SPBE SVCB T UPRO VKCO VTBR WUSH X5 YDEX) — тикер совпадает.
Индексы: IMOEX→IMOEX  MIX→IMOEX  MXI→IMOEX  RTS→RTS  RTSM→RTS.
```

Валидировать словарь по списку акций TQBR (SECID из
`/iss/engines/stock/markets/shares/boards/TQBR/securities.json`). У TATP и SFIN
базового актива на бирже больше нет (выкуплены/делистингованы) — для них линия цены
просто не рисуется, без ошибки.

## 3. Функциональные требования

### 3.1. Главная страница
- **Карточки сводки** (считается как сумма по всем инструментам списка на последнюю
  опубликованную дату): для физлиц и юрлиц — лонг, шорт, нетто (лонг−шорт), доля в
  совокупном объёме (лонг+шорт), число лиц; карточка «Рынок в целом» — всего позиций
  и изменение за день. Карточки физ/юрлиц кликабельны → страница «Динамика по рынку»;
  карточка «Рынок в целом» — не ссылка. Все три карточки одной высоты.
  У метрик — иконки «ⓘ» с подсказками о методике (в т.ч. честная оговорка: «лица»
  суммируются по инструментам и не равны числу уникальных людей).
- **Таблица инструментов**: тикер, название, лонг/шорт физлиц и юрлиц
  (под значением — изменение к пред. дню ▲/▼), всего позиций. Сортировка по любой
  колонке, поиск с дебаунсом, пагинация (25/стр), звёздочка «в избранное».
- **Избранное**: localStorage; режимы «★ Избранное (N)» / «Все инструменты»,
  по умолчанию — избранное (если не пусто), выбор запоминается; при пустом
  избранном — заглушка с кнопкой «Показать все».

### 3.2. Страница инструмента
- **График 1 (сверху) — чистые позиции** (лонг−шорт физлиц и юрлиц, левая ось) +
  **линия цены базового актива** (правая ось; для индексных фьючерсов — индекс).
  Нулевая линия выделена.
- **График 2 — открытые позиции**: 4 серии (лонг/шорт × физ/юр).
- **Кликабельная легенда**: по умолчанию показаны ТОЛЬКО физлица; юрлица и цена
  выключены, включаются кликом. Скрытые серии — приглушённые в легенде.
- **Периоды**: 14/30/60/90 дней, 1/3/5 лет (календарные дни). По умолчанию 90.
  Для периодов > 110 дней даты на оси — с годом (ДД.ММ.ГГ или «сент. 2025»).
- **Агрегаты за период**: открыто/закрыто по каждой категории и стороне
  (закрыто = отрицательная часть дневного изменения, открыто = положительная).

### 3.3. Страница «Динамика по рынку»
- Те же два графика, но по сумме ВСЕХ инструментов списка; линия цены —
  Индекс МосБиржи. Длинные периоды сэмплировать (~90 точек: недели до года,
  месяцы дольше), иначе объём докачки неприемлем.

### 3.4. API (минимум)
```
GET /api/v1/positions?view=open|closed&query=&tickers=SBRF,GAZR&sort=&order=&limit=&offset=
GET /api/v1/positions/summary
GET /api/v1/positions/history?ticker=GAZR&days=90      (+prices, price_label)
GET /api/v1/positions/totals-history?days=90           (+prices — Индекс МосБиржи)
GET /api/v1/instruments?query=
GET /api/v1/system/health      — статус провайдеров + хранилища
GET /api/v1/meta               — справочники режимов
```
Ответы истории несут `source` (какой провайдер ответил, реальные данные или демо).

## 4. Архитектура

```
backend/  FastAPI
  app/api/v1/        эндпоинты (+deps)
  app/services/      DataService (оркестратор провайдеров с фолбэком и «остыванием»
                     после сбоев), PositionService (чистые преобразования)
  app/providers/     moex (позиции), iss (цены), archive (SQLite-кэш-прокси),
                     demo (детерминированный фолбэк: позиции + цены),
                     underlying (словарь), base (интерфейс DataProvider)
  app/storage/       SQLite: snapshots, daily_totals, prices, empty-маркеры
  app/schemas/       pydantic-модели
  app/core/          настройки (env с префиксом FP_), TTL-кэш
  tests/             pytest, работают офлайн на демо-провайдере
frontend/  Vite + React + TS
  src/api/           типизированный клиент + useApi (AbortController) + useFavorites
  src/pages/         PositionsPage, InstrumentPage, MarketHistoryPage, AboutPage
  src/components/    HistoryCharts (оба графика + кликабельная легенда),
                     SummaryCards, common (Info-подсказки, бейдж источника, спиннер)
```

Принципы:
- **Провайдеры** реализуют интерфейс (get_instruments, get_snapshot, get_history,
  get_ticker_on_date, get_totals_history, get_price_history); цепочка
  «архив(MOEX) → MOEX → demo» с фолбэком. ArchiveProvider — кэширующий прокси.
- **SQLite-архив** (`backend/data/positions.db`):
  - `snapshots` (тикер×дата) — все срезы;
  - `daily_totals` (дата) — агрегаты по всем инструментам + счётчик инструментов;
  - `prices` (актив×дата) — цены закрытия;
  - `empty_dates` / `empty_total_dates` — «пустые даты». Пустая дата достоверна,
    только если позже есть данные (защита от лага публикации).
- **Фоновая синхронизация**: при старте и раз в 15 мин — свежий срез + прогрев
  агрегатов за 30 дней. Срез считается полным, если число тикеров совпадает
  со списком инструментов **на эту дату**; неполный — добирается по тикерам.
- Цены: в кэше проверяется покрытие **головы и хвоста** диапазона по отдельности,
  докачивается только недостающее (старые даты и новые — разные сценарии).
- Вся схема SQLite — только `CREATE … IF NOT EXISTS` (см. ловушки).

## 5. Ловушки (каждая была найдена отладкой — не повторять)

1. **Лаг публикации**: свежих «сегодняшних» данных не бывает. Всегда идти назад
   по будням, пока не появятся данные.
2. **Троттлинг web.moex.com**: частые запросы → валидные ПУСТЫЕ ответы. При
   массовой докачке агрегатов обрабатывать даты ПОСЛЕДОВАТЕЛЬНО (инструменты
   внутри даты — параллельно), сначала «пробовать» дату 2–3 ликвидными
   тикерами (GAZR/SBRF/LKOH): все пустые → дата праздника, весь список не тратить.
3. **Состав инструментов зависит от даты**: агрегат даты неполон, если считать
   сегодняшним списком. Для полноты запрашивайте список инструментов на ту же дату.
4. **Ошибочные «пустые» пометки** закрепляются правилом доверия — не ставить их
   на основании единственного штормового прогона.
5. **Схема SQLite**: только `IF NOT EXISTS` — иначе при повторном старте архив
   молча отключается (без предупреждений сервис продолжит работать в медленном
   режиме без кэша — заметить трудно).
6. **Pydantic**: поле модели с именем `date` затеняет тип `datetime.date` при
   вычислении аннотаций на Python 3.14 — импортировать как `from datetime import
   date as Date`.
7. **Генерация дат истории**: идти назад на `days` КАЛЕНДАРНЫХ дней (не ×2+10) —
   иначе 5-летний период запрашивает 3.7 тыс. дат.
8. **Графики длинных периодов**: категорийная ось recharts искажает время при
   неравномерной плотности — длинные сэмплированные ряды сворачивать в
   недельные/месячные точки на клиенте. Подписи дат — с годом при span > 110 дней.
9. **Суммарный лонг всегда равен суммарному шорту** (у контракта есть покупатель
   и продавец) — удобная самопроверка корректности агрегатов; нетто физлиц
   зеркально нетто юрлиц.
10. **«Лица»** по инструментам суммируются с задвоением — не называть это числом
    уникальных людей.

## 6. Приёмочные проверки

- `pytest` — офлайн-тесты всех эндпоинтов на демо-провайдере (фильтры, сортировки,
  неотрицательность «закрытых», агрегаты, цены, фильтр по тикерам).
- `GET /api/v1/system/health` → `{"status": "ok", storage: {...}}`.
- Сверка с биржей: числа на сайте = числа на
  https://www.moex.com/ru/derivatives/open-positions?page=1&filterGroup=0&date=YYYY-MM-DD&assetw=GAZR
  (обратить внимание на год в date=).
- UI: избранное переживает перезагрузку; переключение видов не роняет React
  (строки чужого вида не должны рендериться); легенда скрывает/показывает линии;
  цена покрывает весь выбранный период.

## 7. Запуск

```bash
cd backend  && uv sync                            # окружение + зависимости (uv.lock)
             uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
             uv run pytest                        # тесты (офлайн, демо-провайдер)
cd frontend && npm install && npm run dev          # порт 5173, прокси /api → 8000
make dev | make stop | make test
```

Конфиг — переменные окружения `FP_*` (data_source: auto|moex|demo, db_path,
sync_interval, history_days_max=1825, total_backfill_days=30, fetch_concurrency=8).
Все параметры опциональны; переопределяются через `backend/.env` (файл читается
автоматически) либо переменными перед запуском. Для полностью офлайн-работы —
`FP_DATA_SOURCE=demo` (демо-провайдер отдаёт и позиции, и синтетические цены).

## 8. Не входит в объём

Авторизация и мультипользовательские избранное (localStorage достаточно до
появления аккаунтов), опционы, валютные/товарные фьючерсы, хранение данных старше,
чем отдаёт архив биржи.
```
